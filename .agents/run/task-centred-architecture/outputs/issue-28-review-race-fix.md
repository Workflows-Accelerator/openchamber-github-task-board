## Design: membership versus field freshness

- `issueWriteTrackers` keys `repo#number` (repo-scoped, so identical issue numbers in different repositories cannot collide). Per issue it stores at most one `{ time, pending }` record per field group: `body`, `state`, `labels`, `record` (whole-record incremental admission).
- An edit marks its group pending at optimistic mutation and settles on PATCH completion: success moves `time` to completion time (so a write whose completion crosses a fetch window still wins); failure drops the record (so a failed speculative patch cannot stay fresh forever). Publication protects a group when the write is pending or its time is newer than the response's request start — the response cannot have observed it.
- `reconcileIssueSnapshot` uses the completed snapshot for membership (absent rows, including zero members, are removed), then retains only local rows that have a newer write/admission record — never a blind union of prior membership. `protectIssueFields` overlays protected fields onto provisional page merges without changing membership. Both display and the persistent cache receive the reconciled collection.
- `syncRepoIncremental` records `record` admissions for the issues its scan returned (`mergeIssuePages` emits fresh objects only for scanned items, so the identity diff is the admission set) after the epoch/repo guard. Its watermark write is unchanged; full publication now uses `max(startedAt, existingWatermark)` so an admitted incremental claim is not rolled back to the full request's start. In the real idle path `since` overlaps the prior watermark (`prevWatermark - 10s`), so keeping the newer claim does not skip a coverage window.
- State is bounded: 5-minute TTL for settled records plus a 400-key cap with oldest-first eviction. No timers, no extra requests, no new automatic writes; refresh storms are not introduced (publication still happens once per admitted full refresh).

## Edge reasoning

- Empty and shrinking repositories: no write records means publication still clears membership (existing regression), and absent rows with records older than the response are removed.
- New items from accepted increments: retained only when the admission is newer than the response start; same-number issues in other repositories are distinct keys.
- In-flight and failed edits: pending writes are protected at publication; success extends protection to its completion time; failure drops protection so a later authoritative response restores truth. Failed status moves are reverted on the record a concurrent publication already installed (not just the detached object).
- Incomplete pagination still throws before publication, keeps prior useful rows, leaves last-full-sync and cache untouched; freshness text is unchanged.
- Superseded refreshes and repository switches still publish nothing (epoch/repo guards unchanged).
