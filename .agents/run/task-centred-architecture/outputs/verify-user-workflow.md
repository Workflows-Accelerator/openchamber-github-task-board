## Outcome 1: opening board obtains fresh issues and linked-session activity

### Supported/tested, with limits

- **Source:** `panel/main.ts` host lifecycle at file end: `onReady` applies context then discovers projects; directory/session changes resolve repository. Discovery reads native `.git/config`/worktree pointer and stored links. `autoResolveRepoForActiveContext` prioritizes directory remote, project remote, stored project link, attached session items, then previous repository. `setRepository` calls `fetchIssues()` (around 913–956). Existing project/repository tests cover resolution helpers, not complete host startup.
- **Source + mocked runtime:** `fetchIssues` around 1483–1625 renders persistent cache as an interim result then requests GitHub; cold fetch probe observed one issues GET. In-memory cache returns early within 60 seconds: second call observed **no additional GET**. A reconstructed iframe starts with empty memory, but actual host remount versus retained-panel behavior was not observed. Therefore “every opening guarantees a fresh request” is not established.
- **Mocked runtime:** force refresh requests GitHub regardless of TTL. Refresh button clears comment/page/ETag caches and calls forced fetch (around 8047); existing D12 tests prove direct-read fallback and ETag behavior only with synthetic tokens/host responses. No real credentials used.
- **Source + tests:** `watchActiveProject` around 581–626 registers `host.onSessions(projectId)` and `onWorktrees`, rebuilds session indexes, rerenders views/drawer, and triggers incremental `since=` fetch when a session becomes idle. Existing V2/all-project tests cover projected `{id,data:{repo,issueNumber}}` attachments, repo-qualified matching, changed-issue merge, conditional reads, and bounded concurrency. They do not prove a live session event reaches an open panel.

### Concrete gaps

1. **Reproduced stale membership after successful refresh.** Probe fetched one issue, changed synthetic upstream to `[]`, called `fetchIssues(true)`: second GET succeeded but board still held **one issue**. `issues = issues.length > 0 ? mergeIssuePages(issues, page1Issues) : page1Issues` (around 1568) only merges; full pagination also never removes absent entries. Deleted/transferred/inaccessible issues can survive a successful refresh, and a successful empty repository cannot clear cached rows. Closing an issue is different: endpoint uses `state=all` and normally updates its state. Fix must preserve streaming while publishing an authoritative completed collection; do not simply replace page 1 and discard unseen later pages.
2. **Single-repository response race, source finding.** `fetchIssues` increments `activeStreamEpoch` but does not capture/validate repository and epoch before applying awaited page-1 results, cache keys, and watermarks. `streamRemainingPages` does check identity/epoch; All Projects checks epoch after fetch. Switching repositories during initial GET can apply old results under new current context. Not runtime-reproduced here; add deferred-response test.
3. **Settings same-repository startup, source finding.** `onReady` assigns `currentRepo = ctx.settings.repo`; if discovery resolves exactly that repository, `setRepository` returns before fetching because `currentRepo === repo`. No explicit initial fetch follows discovery. Needs host-ready integration test, not a parser test.
4. **Session freshness/coverage is not represented.** SDK `dist/workspace.d.ts` provides snapshot `state`, per-directory `coverage`, and `activity: unknown|idle|running|retrying|waiting-*`; watcher consumes only `.sessions`. Subscription error merely logs; project ID is set before subscription success, preventing retry for same project. Only active project is watched, even when All Projects contains other projects. No evidence all displayed rows have current session coverage. Also asynchronous project subscription changes have no generation guard; investigate old callback admission before widening subscriptions.
5. **Stale/offline visibility incomplete.** Failure probe retained cached issue and recorded `lastSyncErrorState.kind = offline`. Existing UI renders notice inside repository popover (`renderRepoPopoverList`, around 994), plus a toast on cached fetch failure. No always-visible age/last-success indicator established; `lastSyncTimestamp` initializes to now. Background pagination errors only log. All Projects drops failed repository results, then clears error if any source succeeds (around 1760–1789), making incomplete coverage appear successful. Idle wrapper updates global timestamp even when incremental sync returned false. No visual/browser proof of stale state.
6. **Opening panel is not guaranteed read-only.** `statusReconciler` around 2591 calls `updateIssueStatus`; fetch/session callbacks schedule it. Consequently a live open-board experiment can write labels. Do not open instrumented live panel under this task's no-mutation authority; prove against a recording/no-write host first or obtain separate explicit mutation sandbox authorization. Idle must not be advertised as task completion; SDK outcome is a turn outcome, not task status.
